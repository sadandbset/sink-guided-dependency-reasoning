## Top high-risk sink APIs (complete untrusted-source -> dangerous-path flows)

1. **`send_file` - dataretriever/diamond_store.py:137 (tp, 0.98, arg 0)** - `/obj/<path:obj_path>`: `path = os.path.join(DATAROOT, obj_path)` with no containment check anywhere (diamond_store.py:122-123,130-143). The path-converter param accepts `/` (Werkzeug percent-decodes before routing), so `../../etc/passwd`-style segments or an absolute-style segment escape DATAROOT via `os.path.join` semantics. **The canonical CWE-22 channel of this project.**
2. **`send_file` - dataretriever/mixer_store.py:266 (tp, 0.98, arg 0)** and **`send_file` - dataretriever/test_store.py:296 (tp, 0.98, arg 0)** - identical unguarded `/obj/<path:obj_path>` shape. Note: `test_store.py` is a *production* dataretriever store (BASEURL `cocktailtest`, registered through the DATASTORE config in dataretriever/__main__.py), not a test fixture.
3. **`send_file` - dataretriever/yfcc100m_mysql_store.py:128 (tp, 0.97, arg 0)** - `/obj/<dataset>/<path:rel_path>` -> `os.path.join(DATAROOT, dataset, rel_path)`, unguarded; rel_path is a path-converter param.
4. **`Popen` - dataretriever/video_store.py:162 (tp, 0.90, cmd list arg 0)** - `/obj/start/<int:start>/span/<int:span>/<path:video>`: `video_path = os.path.join(DATAROOT, video)` unguarded, then `ffmpeg -i <video_path>` streams the attacker-chosen file's content to the HTTP response (arbitrary file read). `ffprobe` at :136 (tp, 0.88) is the metadata variant; `os.stat` at :104 (candidate, 0.65) is the adjacent oracle.
5. **`open` - dataretriever/util.py:48 (tp, 0.90, arg 0)** - DiamondTextAttr read channel: `/meta/<path:object_path>` (diamond_store.py:87) -> `join(DATAROOT, object_path)` -> `open(path + '.text_attr')`. Unguarded.
6. **`open` - server/object_.py:293/:314 (tp, 0.88/0.85, arg 0)** - diamondserver-side object loading: `file:` scheme URIs from scope-list objectlists / XDR reexecute object ids are split (`split_scheme`) and opened with no root check (server/object_.py:257-324, reachable via server/search.py:246-277). Authorization is the signed scope cookie; the URI *content* is scope-server controlled, not path-validated. `_HttpLoader` (pycurl) additionally follows `file://` URLs when fetching object ids.
7. **`open` - blaster/cache.py:126 (candidate, 0.75, arg 0)** - `SearchCache.get_search`: over the HTTP evaluate route the key is `[0-9a-f]{64}`-constrained, but the sockjs `start(search_key)` event (handlers.py:553) passes an **unconstrained** client string into `os.path.join(basedir, search_key, 'search')` + `open` + `pickle.load` - traversal yields arbitrary-file read *plus* unsafe deserialization.
8. **`open`/`link`/`copyfile`/`rename`/`utime` in blobcache.py (candidate, 0.55-0.75)** - blob signatures arrive client-supplied from `blob:` URIs (blaster handlers.py:204-209) and XDR `sha256:` filter URIs (server/filter.py:645-671) and are only `.lower()`-ed before `os.path.join(basedir, sig)` - no hex validation, so `../` in a sig escapes the cache dir (read at :99, hardlink/copy into the executable dir at :189/:195, mtime oracle at :83).
9. **`open` - server/filter.py:685/:702 (candidate, 0.70)** - filter code/config files opened at `ExecutableBlobCache.executable_path(sig)` paths chosen by the client's filter code URI.

## Top source APIs

- **Flask path-converter route params (84 source-role entries)** - the dominant family. The path-bearing members: `/obj/<path:obj_path>` in diamond/mixer/test/augment stores, `/meta/<path:object_path>` in diamond/mixer/test, `/obj/<dataset>/<path:rel_path>` in yfcc100m_mysql, `<path:video>` in video_store, `/id/<path:object_path>` in diamond/mixer/test/augment - all percent-decoded by Werkzeug before routing, all reaching `os.path.join` (unguarded everywhere except augment_store).
- **XDR RPC params (11 entries)** - unauthenticated raw-socket clients (ports 5874/5904): `setup` filter `sha256:<sig>` URIs and `reexecute_filters` object ids reach BlobCache path builders and `file:` URI opens (tp 0.75-0.8).
- **Tornado/sockjs blaster (9 entries)** - POST /search JSON bodies carrying `blob:<sig>` URIs (tp 0.85) and the unconstrained websocket `start(search_key)` (tp 0.88).
- **Django scopeserver views (27 entries, tp 0.8)** - genuine permission-protected boundaries; form-cleaned data feeds `generate_cookie` scopeurls -> cross-service chain, no direct file access in any view.
- **Not sources (labeled none/fp):** `os.environ['TMPDIR']` (server-set by server/child.py:62), `os.environ['HOME']/['DIAMOND_CONFIG']` (operator config lookup), the environ *write* at server/child.py:62, client-side HOME reads, internal `mixer_list` parameters (never URL-bound), int-converter route params (numeric only), hex-regex-constrained Tornado route params, `dest_url`/`vdms_host`/`condition_expr`/`dataset`/`expression`/`suffix` (SSRF/SQLi/eval/S3-URL concerns of other passes, not path traversal).

## Sanitizer list

**Exactly one: `werkzeug.utils.safe_join` - dataretriever/augment_store.py:156 (tp, 0.9).** It rejects absolute filenames and any `..` segment that would escape the base directory (posixpath.normpath containment check inside werkzeug) and is applied to every augment_store channel (`get_scope` rootdir, `/id/<path:object_path>`, `/obj/<path:obj_path>`), making that store's `send_file` (fp, 0.85) and `open`s (fp, 0.7-0.75) contained. Recorded caveats: (a) symlinks inside DATAROOT are not resolved - a symlink planted under DATAROOT can still point outside the base; (b) every other store uses a bare `os.path.join(DATAROOT, user_path)` - no containment, no `..` rejection, no `normpath`/`realpath` comparison, no basename extraction, no `startswith` guard. `MySanitizers.qll` in Phase 2 will contain the single safe_join entry.

## Audit answers (per the labeling contract)

1. **Source trust:** genuinely untrusted path inputs are the Flask path-converter route params, the blaster JSON/websocket channels, and the XDR RPC params. A route param is *not* auto-trusted: int-converter params (gigapan_id/lvl/col/row, index/total/start/limit, stride/span, seq_no, divisor), hex-regex-constrained Tornado params, default string-converter params that never reach a join as a multi-segment path (gididx/baseidx/mixeridx under the `GIDIDX` prefix), and internal parameters (`mixer_list`) were individually downgraded to fp/none. Env vars are deployer/server trust (TMPDIR is even set by the server itself).
2. **Path transformations:** every step was traced in real code: route param -> (percent-decode by framework) -> `os.path.join(DATAROOT, x)` -> `send_file`/`open`/`Popen`/`os.stat` (stores); `json body -> blob: URI -> urlparse(parts.path) -> BlobCache._path -> open/link/utime` (blaster); `XDR setup -> sha256: URI -> split_scheme -> sig.lower() -> executable_path -> open/Popen` (server); `XDR reexecute -> object_id -> split_scheme(file:) -> open` (object loader). No `unquote` calls exist anywhere in the audited tree, so no double-decode hazard; `split_scheme` is a pure urlparse split (no decoding).
3. **Sink validity:** only real file read/write/delete/stat/archive/process-path APIs carry the sink role (38 entries: `send_file`, `open`, `Popen` file args, `os.stat`, `utime`, `rename`, `link`, `copyfile`, `ZipFile(path)`). `os.path.join`/`dirname`/wrapper functions are labeled **summary** (70 entries) - propagation, not sinks; `os.path.isfile/exists/isdir` checks are labeled `none` (existence oracles); `Path(...)` is not used in this codebase; `ZipFile(BytesIO(...))` sites (filter/__init__.py:121/126, proxy/search.py:214, client/util.py:33) are in-memory and labeled none/fp; gigapan `send_file` receives a *stream object*, not a path.
4. **Escape potential:** `os.path.join(DATAROOT, p)` lets an absolute `p` replace the base entirely and `..` segments climb out - confirmed reachable via the `<path:...>` converters in diamond/mixer/test/video/yfcc100m_mysql stores (no guard at all) and via unvalidated blob sigs (`join(basedir, sig.lower())`) and the unconstrained websocket search_key (`join(basedir, key, 'search')`). Backslash/drive-letter variants are Windows-only concerns; the deployment is POSIX (pwd/grp usage in dataretriever), so not applicable. Repeated decoding: none (see #2).
5. **Containment checks before file access:** exactly one - `safe_join` in augment_store.py:156 (normpath-based containment, executes before the join result is used). No `relative_to()`, no fixed-filename mapping, no whitelist anywhere else. The `GIDIDX`-prefix convention plus the no-`/` string converter incidentally blocks index-file traversal in diamond/mixer/test/video stores (documented per-entry as fp, not as a sanitizer).
6. **Function-name-only sanitizers:** none assumed. `sig.lower()`, `gididx.upper()`, `classes.replace('%2C', ...)` (result discarded - a no-op bug, noted), `os.path.isfile/exists` checks, route regexes, `urlparse`, and scope-cookie signature verification are all explicitly recorded as NOT traversal sanitizers (regexes/cookies are authorization, checks are oracles).
7. **Symlinks/TOCTOU:** no `realpath`/`lstat`/symlink-aware validation anywhere; `safe_join` itself documents the symlink caveat. TOCTOU-by-design exists in BlobCache GC (stat/rename/unlink races, blobcache.py:28-54) and `mktemp()` is used in `ExecutableBlobCache.make_dest` (blobcache.py:188) - both recorded in detection.json and per-entry rationales; no symlink-exploitation chain was found in the reachable flows, so beyond the safe_join caveat it is recorded as not applicable.
8. **Authorization vs vulnerability:** serving files under DATAROOT to scope-cookie-authorized clients is the intended function; the vulnerability judgment is about *escaping the declared root*, not about the serving itself. `@permission_required` (Django), `@_restricted` (blaster), the signed scope cookie and the hex route regexes limit the attacker population but do not constrain path content (django.md section 8) - they are contextual, never sanitizers.
9. **Tests/fixed constants/unreachable code:** `tests/` was excluded at extraction; `test_store.py`/`test_utils.py` are runtime production modules (registered via DATASTORE config) and were labeled as such; fixed-literal paths (`/dev/null`, `yfcc100m.csv`, log/cache defaults) and operator-config/CLI paths (config.py, scope.py `_main`, blaster options) are fp; the nested `opendiamond-db/` tree was never traversed. Database-directory generated files do not appear among the candidates.
10. **Flow completeness:** the diamond/mixer/test/yfcc100m_mysql `/obj` channels, the video `/obj/.../<path:video>` ffmpeg channel and the diamond `/meta` attribute channel are complete untrusted-source -> dangerous-path-argument flows. The blaster blob-sig channel and the XDR setup/reexecute channels are complete but end in cache-internal joins (labeled candidate pending review of sig constraints). The blobcache/blaster-cache `link`/`rename`/`utime` entries are local wrapper -> fs-API fragments whose exploitability depends on those upstream sig/key channels. The Django views -> `generate_cookie` -> dataretriever `file:` URI chain is a cross-service flow (needs Phase 2 MySummaries; endpoints labeled, chain flagged).

## Unresolved / low-confidence items (human review points)

1. **Blaster websocket search_key (blaster/cache.py:126, candidate 0.75):** confirm the sockjs c2s event schema (`_c2s_event_schema`) does not restrict `search_key` to hex - if not, the `open`+`pickle.load` at an arbitrary `join(basedir, search_key, 'search')` path is a traversal + deserialization channel, and the pickle aspect belongs to Pass 6 as well.
2. **Blob-cache signature validation (blobcache.py:99/:189/:195, candidate 0.6-0.75):** verify whether any upstream (blaster `_BlasterBlob.fetch`, XDR filter URIs) constrains `blob:`/`sha256:` URI paths to hex in a version not visible in this tree; as written, `sig.lower()` is the only transformation.
3. **XDR reexecute object ids (server/object_.py:293/:314, tp 0.85-0.88):** decide the threat model for RPC clients holding a valid signed scope cookie - the cookie gates *which scopes* may be searched, but `reexecute_filters` accepts client-chosen object ids whose `file:` paths bypass the scope list entirely; also confirm pycurl's `file://` handling in `_load_src_maybe_meta`.
4. **Cross-service chains (scope.py:253 generate_cookie, candidate 0.55):** the Django form -> scope cookie -> dataretriever objectlist -> `file:` URI -> `open` chain needs MySummaries edges in Phase 2 (single-DB taint cannot see it end-to-end).
5. **`classes` route param listing effect (mixer_store.py:200 / test_store.py:229, candidate 0.6):** a `..` class name only shifts which images are *listed*; confirm the review position that listing alone (content still gated by `/obj`) is an oracle, not a traversal sink.
6. **Sanitizer scope:** confirm the single-entry sanitizer decision (only augment_store is guarded) before Phase 2 barrier wiring - `MySanitizers.qll` will carry exactly the safe_join site.
